# Raspberry Pi: камера Logitech и MLX90640 → станция по Wi-Fi

Pi только снимает и отправляет. Детекция идёт на ноутбуке, в `interface/`.

```
Logitech USB ──► Pi: ustreamer :8080/stream (MJPEG, без перекодирования) ──Wi-Fi──► ноутбук: interface (Pi cam) → детектор
MLX90640 I2C ──► Pi: mlx_stream (UDP :5005)                              ──Wi-Fi──► ноутбук: interface /thermal
```

## 1. Сеть: Pi, ноутбук и всё остальное подключены к одному модему

```bash
sudo ./webcam_setup.sh wifi SAR-MODEM 'пароль-модема'
sudo ./webcam_setup.sh wifi SAR-MODEM 'пароль-модема' 192.168.8.50/24
```

Первая команда подключает Pi к модему с адресом от модема. Вторая делает то же самое, но с постоянным адресом Pi: шлюз берётся как `.1` той же подсети, а если у модема он другой, его можно передать четвёртым аргументом.

- **Настроить можно заранее.** Модем не обязан быть рядом: профиль `sar-modem` сохраняется, и Pi подключится сама, как только модем появится. Пробует она бесконечно, так что неважно, что включится раньше.
- **Адрес Pi в интерфейсе.** Это `<hostname>.local:8080` (у нас `thermal.local:8080`) или постоянный IP, если вы его задали. Если `.local` не находится, узнайте IP в веб-панели модема или командой `./webcam_setup.sh status` на Pi. Лучше задать постоянный IP или закрепить адрес за Pi в настройках модема (DHCP reservation).
- **В модеме должна быть выключена изоляция клиентов** (AP isolation / client isolation / «гостевая сеть»). Иначе устройства выходят в интернет, но не видят друг друга, и ноутбук получит `No route to host`. Именно это у нас было в сети `192.168.0.x`.
- **Точка доступа Pi** (`hotspot`) остаётся запасным вариантом. Команда `wifi` выключает её автозапуск, а `sudo ./webcam_setup.sh hotspot SAR-PI 'пароль'` возвращает.

Если вы зашли на Pi по SSH через Wi-Fi, после переключения сети SSH оборвётся, это нормально. Само переключение скрипт выполняет в фоне (лог в `/var/log/wifi-switch.log`). Если страна Wi-Fi не задана, скрипт ставит `KZ`. Другая страна: `COUNTRY=XX sudo -E ./webcam_setup.sh ...`.

## 2. Камера

Скопировать скрипт на Pi и поставить:

```bash
scp raspberry/webcam_setup.sh pi@raspberrypi.local:~
ssh pi@raspberrypi.local
sudo ./webcam_setup.sh install
```

Скрипт ставит `ustreamer`. Сервис `webcam-stream` запускается при загрузке и перезапускается, если камеру выдернули и вставили обратно. Проверить можно в браузере ноутбука: `http://<hostname>.local:8080/stream` (у нас `http://thermal.local:8080/stream`).

Камера Logitech сама сжимает кадры в MJPEG, поэтому Pi их только пересылает (`ENCODER=HW`). Нагрузка на процессор почти нулевая, подходит даже Pi Zero 2 W. Настройки лежат в `/etc/default/webcam-stream`, после правки нужно `sudo systemctl restart webcam-stream`:

| Параметр | По умолчанию | Примечание |
| --- | --- | --- |
| `RESOLUTION` | `1280x720` | C920/C922 умеют `1920x1080`. Режимы камеры: `./webcam_setup.sh status` |
| `FPS` | `30` | 720p×30 — это около 20–25 Мбит/с. Если по Wi-Fi тормозит, ставьте 15 |
| `PORT` | `8080` | |
| `DEVICE` | `/dev/v4l/by-id/usb-046d…` | находится при `install` |
| `ENCODER` | `HW` | `CPU`, если камера не отдаёт MJPEG или сервис не стартует (`journalctl -u webcam-stream`) |

## 3. На ноутбуке

```bash
cd interface && npm run dev
```

Подключите ноутбук к тому же модему. Откройте http://localhost:8765/#pi, введите адрес Pi (`thermal.local:8080` или постоянный IP) и нажмите **Connect**. Адрес запоминается. Адрес по умолчанию задаётся при запуске: `PICAM_URL=http://thermal.local:8080/stream npm run dev`.

Ноутбук держит одно соединение с Pi, сколько бы вкладок ни было открыто. Сцена показывает поток плавно, а детектор берёт самый свежий кадр, без перекодирования. Дальше всё работает как в режиме Camera: модели, tiling, список найденных людей, экспорт JSON.

Проверка без Pi: `python raspberry/fake_cam_stream.py` (нужен ffmpeg), затем в интерфейсе адрес `localhost:8080`. С записью дрона: `--video drone.mp4`.
